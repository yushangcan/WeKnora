## 2. 线上验收发现并修复的问题

### 2.1 Wiki Token 统计和缓存证据应分别保留

先前汇总逻辑在 `CacheReported=false` 时直接跳过整条事件，导致 Provider
已经返回的 Prompt Token 也被丢弃。现在 Prompt Token 累计所有明确上报的值；
缓存命中率只统计明确上报缓存信息的调用。

缓存 Token 比例的分子和分母必须来自同一批调用：只有一条事件同时具备
Prompt Token 与 Cache Read Token 时，才计入比例。不能将一条调用的分子
和另一条缺字段调用的分母拼接，也不能用缺少缓存信息的调用稀释命中比例。
缺失值仍保持 NULL。

### 2.2 用量来源与金额来源分开验证

两项旧测试仍把 `provider_reported` / `catalog_calculated` 写在
`UsageSource` 的断言中。当前持久化契约已拆分为：

- `UsageSource=provider` 表示用量来自 Provider；
- `CostSource=provider_reported` 表示金额来自 Provider；
- `CostSource=catalog_calculated` 表示金额按版本化价格目录计算。

修复后的测试同时检查这两个字段及金额、币种、价格版本，避免再次混淆。

### 2.3 缓存指标测试明确统计口径

Hit/Miss Items 统计输入位置，因此相同文本出现两次且均未命中时计两条 Miss。
Provider Items 统计去重后实际交给 Provider 的文本。测试现在同时验证这两种
统计，而不会用去重后的数量代替原始输入数量。

缓存故障计数按真实后端操作统计：首次 Get 与 singleflight 内部复查均失败，
应记录两次 Get Error；Provider 仍调用一次，正常返回向量。这里修正的是
旧测试期望，保留已实现的协调和降级行为。

### 2.4 CMRC2018 固定来源与离线回归

转换器过去虽然输出文件哈希，却没有强制检查输入是否来自声明的固定版本。
现在先读取一次源文件，核对 validation split 的固定 SHA-256，再从同一份
字节解析 Parquet。替换为训练集、测试集、其他版本或修改后的内容都会失败。

新增不依赖 `raw/` 的五项测试，覆盖来源拒绝、中文字符偏移、无效标注、
完整检索语料保留、稳定选择及既有输出保护。原始 validation 文件存在时，
原有完整转换测试继续执行；在缺少原始文件的 CI 上仅该项测试会跳过。

本机实际校验的固定源文件有 3,219 行，包含 848 个不同上下文；3,216 行
具备至少一个有效抽取答案。审计记录 210 条无效答案标注和 3 条无有效答案
的问题。默认选择 200 个有效问题，保留全部 848 个上下文作为检索语料。
这些数字来自数据转换测试，不是模型测评得分。

### 2.5 CI 触发、失败传播和证据文件

三个专项 workflow 支持 `main` 和 `codex/evaluation-**` 分支推送，保留 PR
和手动入口。模型用量与 CMRC 转换测试已纳入自包含 CI 的构建检查。

Linux 构建限制 Go 并发以适应 runner。迁移与缓存 workflow 使用显式 Bash
shell，使 `go test | tee` 等管道正确传递失败退出码。迁移版本命令的输出
位于 stderr，现在同时捕获并检查文件非空，避免上传空的版本记录。

标准 App 同时编译 SQLite 向量扩展，即使运行时选用 PostgreSQL，也需要
`sqlite3.h`。CI 构建容器已按项目原有 Dockerfile 安装 `libsqlite3-dev`。

PostgreSQL 健康检查使用 TCP，防止初始化阶段临时 Unix socket 提前报健康。
验收容器使用宿主调用者的 UID/GID：CLI 创建的 `0600` 报告既保留访问权限，
也能被同一宿主用户运行的 artifact uploader 读取。

## 5. 课题提交对齐与召回口径修复

根据课题三“质量评测基线与成本可观测”验收要求，提交 `1f114dda` 在合成
环境补充真正降低召回的负向场景。首次运行 `34758574410` 失败并揭示一个
实际问题：重排结果被全部过滤后，指标和 Case 证据按非空判断回退到 SearchResult，
造成最终无相关上下文时 Recall 仍为 1。

修复 `8945b5b2` 在运行态记录 RerankCompleted，区分成功重排的空结果与跳过或
失败回退。指标和证据选择条件一致，完成但为空时 Recall 按空输入计算；
`EvaluationMetricVersion` 升为 `retrieval-generation/v3`，保持旧报告口径可区分。
新增回归覆盖两种分支的 Recall 与证据一致性，实际合成 CI 继续验证端到端场景。

最终 Actions `34759714335` 完整通过；报告已核对，正常 Recall 为 1，召回
退化为 0，gate 明确输出 `recall delta -1.000000`。空上下文分支跳过 Chat，
所以仅要求保留真实调用事实，允许 generic Embedding/Rerank 未上报 Token。
这项修正属于测试对真实回退行为的适配，不伪造缺失 Usage。

提交材料位于 [docs/submission](submission/README.md)，包含当前详细设计、
逐项验收状态和精选原始证据。GitHub 默认分支尚未合入本分支的 workflow，
main 未启用分支保护；代码中的定时与 gate 能力不等于默认分支配置已经生效。
